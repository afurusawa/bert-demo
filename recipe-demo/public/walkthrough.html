The lab process

A changed head needs calibration

A recording head writes bits and reads them back. After a head change, the lab adjusts 12 chip settings, called registers, until the bit error rate is acceptable.

The final settings are a recipe. A lower bit error rate means fewer bits came back wrong.

A starting recipe is only the first guess. The calibration suite still has to qualify it.

Past examples

The demo learns from completed logs

Each old log says what kind of head change happened, what the first electrical read showed, and which 12 settings the suite finished with.

The demo learns a shared base recipe, which registers usually move for each change type, and small rules connecting the first read to those moving settings.

The 80 test heads stay out of learning. Their hidden answers appear later only for comparison.

A new head

First, check whether its story fits

The new head arrives with a claimed change type and four first-read measurements. The model compares those measurements with the known training groups.

It refuses the learned map if the claimed type is unsupported, another known type looks closer, or the measurements are unusually far from that type's examples.

Passing this check permits a proposal. It does not prove the type or approve the settings.

The decision

Offer a start, or refuse the map

For an accepted claim, the map predicts values for registers it learned to move. Other registers use the shared base value. The resulting 12 values form an unchecked starting recipe.

On refusal, the page gives no mapped start and tells the viewer to run the full approximate suite. Its aggregate comparison uses “copy last” as the fallback starting point for that head.

“Skip” means use the shared base setting, not keep the previous head's setting.
